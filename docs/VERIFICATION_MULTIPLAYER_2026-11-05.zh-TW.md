# 真實多帳號與衝突驗收

驗證期間：2026-11-04 至 2026-11-05（Asia/Taipei）。分支：`feature/release-readiness`。網站採 production build，三個分頁各自使用 Firebase in-memory Authentication。

## 環境與範圍

使用者在 `travel-os-first-run-test` 建立 editor／viewer 測試使用者，另有既有 owner。Console 顯示此專案為 Blaze／免費試用；本輪未變更方案。不能將此結果記為獨立 Spark 專案驗收。

只分享既有的合成驗收旅程；owner 的其他四趟旅程未分享。沒有把密碼、Web config、真實 Email 或測試 UID 寫入本報告。

## 實際結果

- 三個角色分別完成設定精靈與登入。授權前，editor／viewer 清單沒有 owner 的旅程。
- owner 重新登入後，跨年租車、住宿、分組資料及 USD 100／TWD 300 兩筆費用皆讀回；已刪除的 TWD 1 暫存費用沒有回來。
- owner 加入 editor／viewer 後，兩個分頁不需重整即收到同一趟合成旅程；各自只有這一趟，沒有 owner 的其他旅程選項。
- editor 介面顯示「編輯者」，成員管理停用。viewer 顯示「檢視者（唯讀）」，新增群組、群組管理、新增費用、編輯費用及成員管理停用。
- editor 修改一筆費用備註並保存，owner 與 viewer 即時收到相同內容；金額與分攤資料保留。
- editor 開啟舊版費用表單，owner 先修改同筆費用並保存。editor 再保存時顯示「旅程已更新，請保留內容並重新開啟費用」，草稿保留；owner／viewer 仍顯示 owner 的新版本，未遭覆蓋。
- owner 經站內二次確認移除 editor 後，editor 的旅程清單立即清空。已開啟的表單提示旅程刪除或權限移除，草稿保留；再次保存被阻止，owner／viewer 最新資料保留。
- 重新加入 editor 後，合成旅程恢復出現；最後保留 owner／editor／viewer 三個測試角色。
- editor 另建自己的跨年合成旅程，owner／viewer 的清單沒有出現它。該旅程從 0 群組新增為 1、2 群組，更名成功；切回分享旅程後，自己的群組沒有混入，原費用與備註讀回。尚未測本輪雲端群組刪除／關聯移轉。

撤銷後重新授權時，舊版介面雖收到資料，仍殘留「即時更新失敗」提示。已修正為收到目前旅程的有效更新後顯示「已接收目前旅程的最新資料」，僅描述實際收到的資料，不將其視為所有權限測試成功。重建後的新工作階段仍須重測此提示。

## 設定貼上修正

從 Console 顯示的程式碼選取文字可能包含 U+00A0 非斷行縮排，原 parser 將它交給 JSON.parse 而失敗。現在僅將引號外的非斷行空白正規化，引號內文字保留，仍使用 JSON.parse，沒有 eval。

增加一項回歸測試，確認非斷行縮排可解析、引號內內容不變、可執行運算式仍被拒絕。173 項單元測試與 production build 通過。實際瀏覽器確認載入修正版 `index-CbR8A_5A.js`，貼入含非斷行縮排的合成 config 後由 Step 2 成功進入 Step 3；未對合成設定發出登入或資料庫請求。

介面停用與授權前清單為空，不等同真實 SDK 繞過介面的越權請求測試。viewer 直接寫入、editor 直接升權、已登入者跨旅程直接讀寫，仍需補齊實際服務證據；既有 40 項 Rules Emulator 證據保留。獨立 Spark 新手流程、跨專案切換、正式 Pages 與最終發布門檻仍依 RELEASE_ACCEPTANCE 核對。
