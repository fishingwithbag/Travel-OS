# 真實 Firebase 權限驗證

日期：2026-11-06。候選程式基線：`a6ba6ad`。本輪使用建立者既有測試專案、三個網站 Authentication 帳號及三趟合成旅程；沒有要求旅伴建立 Firebase／Google 帳號，也沒有更動計費方案。

## 結果

真實 Firebase SDK 請求共 **21 項 PASS、0 項 FAIL**，包含 **13 次伺服器拒絕越權讀寫**。這不是只確認唯讀按鈕停用，也不是以 Emulator 代替真實服務。

| 檢查 | 實際結果 |
|---|---|
| owner、editor、viewer 登入及共同旅程讀取 | 三角色成功 |
| 未登入者讀取／寫入 | 兩項均拒絕 |
| viewer 提交完整且結構合法的旅程版本 | 拒絕 |
| editor 修改 viewer 角色／自行升為 owner | 兩項均拒絕 |
| editor、viewer 讀取／寫入 owner 私有旅程 | 四項均拒絕 |
| 共同旅程的 owner 讀取／寫入 editor 私有旅程 | 兩項均拒絕；owner 權限限於所屬旅程 |
| viewer 讀取其他使用者的旅程索引 | 拒絕 |
| editor 發布合法完整版本，viewer 重新讀取 | 成功讀回版本 2 |
| viewer 在最新版本上再次提交合法內容 | 拒絕 |
| 拒絕後重新檢查版本與角色 | head 維持 2，三角色權限完整 |

其餘 PASS 為登入、合成資料準備及最終狀態確認，不將 21 項全部描述成越權測試。三趟合成旅程保留供追查，沒有刪除既有使用者旅程。

## 驗證工具的修正

第一次執行在匿名讀取處停止：SDK 的讀取錯誤為 `Error("Permission denied")`，沒有 `code`；驗證工具當時只辨識錯誤碼，將實際拒絕誤判為未知失敗。修正工具以確切錯誤訊息及已知拒絕碼辨識，並通過 8 項分類檢查；網路、未知及登入錯誤不會因此算作權限拒絕。

重新登入後重用原三趟合成旅程，完整重跑通過。此修正僅影響被 Git 忽略的本機驗證工具，沒有為通過測試放寬產品 Rules 或修改服務端角色。
