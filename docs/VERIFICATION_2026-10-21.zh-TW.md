# 第 1 包：正式資料完整性整合驗證

日期：2026-10-21（Asia/Taipei）。本報告只關閉本包的開發與本機驗證，整體發布門檻仍未通過。

## 已實作

- 正式 Firebase adapter 的建立、讀取、訂閱、保存與備份還原接入 head／不可變完整版本。保存由伺服器拒絕過期 revision，原子移除上一版，避免歷史持續成長。
- 正式 Rules 不再授予既有旅程的廣泛 owner 寫入權限。owner/editor 也不能局部修改已發布版本；完整新版本重驗欄位及群組參照。owner 保有成員管理與整趟刪除權限。
- 舊格式維持可讀，owner 下載私人備份並確認後才逐趟遷移；保留原資料副本及成員。遺失群組在預覽列出原 ID 與復原名稱，不靜默丟棄行程或停車資料。
- 精靈 Step 5 加入儲存格式診斷標記，舊 Rules 會拒絕並提示回 Step 2 更新。診斷不宣稱完整安全稽核。
- 更新升級／回復、群組修復、協作與備份文件。Vite 由 7.3.6 修補至 7.3.7，處理 npm audit 新公布的 high 風險；僅變更此一套件鎖定版本。

## 測試證據

| 驗證 | 結果與範圍 |
|---|---|
| 單元及建置 | 153 個單元測試通過，production build 通過 |
| 正式 Rules | 兩份測試共 40 個通過；不再使用實驗替代 Rules |
| 局部寫入 | owner/editor 直接刪除群組或改已發布版本被拒絕 |
| 新版本參照 | 孤立行程群組及分組停車參照被拒絕，合法完整移轉成功 |
| 歷史容量 | 發布新 head 時必須原子移除上一版；不能先預埋下一版或保留舊版造成一般保存持續成長 |
| 遷移 | editor/viewer 不能遷移；錯誤版本與錯誤參照原子拒絕，舊資料保持原值 |
| 完整資料與回復 | SDK 遷移保留 groups/items/places/rentals/stays/expenses，備份可驗證並還原為新 owner 旅程；不複製成員、不覆蓋來源 |
| 競爭保存 | 兩個 Firebase SDK 用戶端同 revision 同時保存，恰好一個成功，另一個收到衝突，只有成功者的完整版本留下 |
| 精靈版本檢查 | 現行診斷對舊版診斷 Rules 失敗；現行 Rules 拒絕舊格式診斷 |
| 瀏覽器 | 親自操作網站精靈、舊旅程唯讀、下載備份、未勾選禁止確認、群組修復預覽、確認升級、編輯並保存下一版本 |
| 下載檔 | 實際取得檔案後驗證標準備份可還原，原始遺失群組資料與備註保留 |

瀏覽器驗證使用獨立 demo Emulator namespace 與測試身分 adapter；資料庫仍使用真實 Firebase SDK 及正式 Rules。登入 adapter 只在忽略的本機測試伺服器注入，沒有進入正式程式或建置。不以此宣稱真實 Authentication 或 Spark 已驗收。未升級帳戶、未修改雲端計費、未呼叫 Google 付費 API。
