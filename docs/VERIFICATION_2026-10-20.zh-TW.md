## 後續：群組完整性與零費用限制

### 群組本機實測

使用獨立合成備份，包含兩群組、行程、分組停車、租車、住宿及三人分攤費用。實際瀏覽器完成匯入預覽、A 組移至 B 組、最後一組移至所有人／共用、重整及完整 JSON 匯出。每次均出現五類影響數量與第二次確認。

匯出檔經 domain 驗證，逐一比對 groups/items/rentals/stays/expenses/places 六個集合與預期相同，revision 正確增加兩次；入口／停車備註、步行 0 分鐘、USD 5 停車資訊、USD 40 租車、USD 80 住宿與 USD 10 三人分攤均保留。本項只關閉該本機移轉案例，不代表任意直接 RTDB 局部寫入問題已解決。

### 公開資料掃描範圍

掃描當時全部 refs 可達的 53 個 commits 及 dist：檢查 Google Key 格式、私鑰標記、已知測試專案／帳號識別與本機使用者路徑。匹配項目經核對為拒絕私鑰的程式標記，以及由重複數字構成的合成 Key 測試資料；本次範圍未發現真實憑證。這不是對所有個資類型、第三方素材及授權的全面保證，最終發布審查仍須完成。

### 不升級、零實際費用

使用者要求所有帳戶不得升級、不得產生實際費用。真實 Google API 驗證暫未進行，不能把試用抵免當成長期免費的依據，也不因而刪除既定功能。

設定精靈 Step 3 已增加事前提醒：免費試用會到期；帳單連結同一 Firebase 專案會自動轉成 Blaze；Travel OS 不代為升級，也不能保證 Google API 永遠零費用。需要確認長期符合零費用要求的技術與服務條件後，才能通過此發布門檻。專案 ID、帳號與帳單識別不寫入公開報告。

一般安排表單亦明確說明時長／重疊使用當地鐘面時間，不代表跨夏令時間的實際經過分鐘。
