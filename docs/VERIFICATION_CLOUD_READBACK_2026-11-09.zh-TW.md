# 獨立登入、雲端讀回與暫存景點清理

日期：2026-11-09。在新的獨立分頁以既有網站帳號登入；帳號持有人只在瀏覽器輸入密碼，沒有重設 Firebase 或建立新帳號。

## 雲端資料讀回

- 清單讀回四趟獲授權旅程，包含前次網站自建旅程、備份還原副本及兩趟既有共享合成旅程。
- 自建旅程與副本均保留兩群組、一筆住宿、一筆租車與兩筆費用；原旅程三筆安排，副本四筆安排及一個收藏景點，符合還原後新增景點的狀態。
- 跨年入住／退房、取還車日期時間、JPY 住宿費、USD 100／TWD 300 支出，以及三人分攤餘數均正確。
- 兩趟自建旅程的身分為 owner；切回他人共享旅程仍為 viewer，新增群組、費用及成員管理停用。建立自己的旅程不會升高其他旅程的權限。
- 明確選取 B 組並核對 `aria-pressed=true` 後，下一站僅顯示 B 組停車與步行 7 分鐘；A 組目前站僅顯示 A 組停車與步行 3 分鐘。初次探查停在所有行程時看到全部組別，不將未選中篩選誤報成修正版失效。
- 原旅程仍保留共用主備停車；副本的獨立分組資料沒有覆蓋原旅程。

## 主備停車與幣別

在本輪副本補上 A／B 各自的備用停車及 Maps 連結；A 主停車預估費用 TWD 50，B 主停車 JPY 400。雲端確認保存後，B 組下一站僅顯示 B 主備停車、JPY 400 及步行 7 分鐘。支出總額仍為 USD 100／TWD 300，停車預估費沒有被混入支出。

下載的完整雲端備份核對到兩個不同群組的主備停車、幣別與整數儲存值；沒有只以畫面中的未保存表單當成成功。

## 已授權的暫存景點清理

沿用使用者先前允許清理「驗收暫存景點」的授權，只在本輪自建副本新增一個明確命名的可刪除合成景點，並排入第三天。

1. 刪除景點前顯示影響提示；確認刪除景點庫項目後，已排入每日行程的安排仍保留。
2. 再以安排的獨立確認流程清理該筆暫存安排。等待雲端確認後，第三天為空白；既有收藏景點仍在。
3. 最後重新下載雲端備份：副本兩群組／四安排／一景點／一住宿／一租車／兩費用，原旅程兩群組／三安排／零景點／一住宿／一租車／兩費用。兩者皆無本輪暫存景點或安排，其他旅程保留。
