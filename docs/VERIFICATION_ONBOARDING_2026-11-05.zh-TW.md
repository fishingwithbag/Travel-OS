# 建立者與旅伴流程驗證（2026-11-05）

本批將「旅伴不需要 Firebase Console 資格」落實為網站行為。建立者匯出經驗證的公開 Web config，透過自己 repository 的 Actions secret 發布；新裝置只需網站 Email／密碼登入。不變更帳戶方案、不新增後端，也不把 Firebase 管理憑證放進瀏覽器。

## 已取得證據

| 項目 | 實際結果 | 邊界 |
|---|---|---|
| 設定 parser、同站子路徑、錯誤／憑證拒絕 | 178 項單元通過，含 5 項網站設定測試 | 不等於真實帳號登入 |
| 權限與建置 CI | 提交 `ebc4dcd` 的 [CI](https://github.com/fishingwithbag/Travel-OS/actions/runs/42003383562) 全部成功，含 40 項 Rules 測試、build 與依賴稽核 | 後續版面修正另提交並由 CI 重跑 |
| 實際 production preview | 有網站設定時直接顯示網站 Email／密碼；六步導覽、Firebase 記住選項及設定匯出入口隱藏 | 真實 viewer 登入仍需帳號持有人輸入既有密碼 |
| 桌面登入版面 | 發現隱藏側欄後內容仍落在窄欄，修正為 540px 單欄視窗；實際 DOM 量測寬度 540px，無內部水平溢出 | 原六步精靈仍使用原有版面 |
| 手機登入版面 | 390px、320px 實際瀏覽器檢查，視窗及頁面無水平溢出；已保存畫面證據 | 長頁面可垂直捲動，不代表全站手機驗收完成 |
| 空白登入 | 顯示「請輸入網站 Email 與密碼」，保留登入入口 | 未用猜測密碼測試帳號 |
| 通用建置 | 不帶網站設定時，產物沒有 `site-config.json`；原始碼中的本機設定檔被 Git 忽略 | 操作者自己的部署會包含公開 Web config，這是預期行為 |
| 根路徑及 repo 子路徑 | 靜態產物在根路徑與 `/Travel-OS/` 均正常載入樣式與六步精靈 | 仍須正式 Pages 發布後重測 |
| 子路徑本機保存 | 建立跨年三日合成旅程，重整讀回，無水平溢出；切到根路徑時未混入子路徑旅程 | 本機模式證據不替代雲端證據 |
| 真實服務匿名讀取 | 測試專案資料庫根目錄、已知合成旅程及 userTrips 路徑均回傳 HTTP 401／Permission denied | 不能替代 viewer 寫入、editor 升權或已登入跨旅程直接請求測試 |

本機 Emulator 首先遇到預設 Java 17 版本不符；指定既有 Java 21 後遇到 Windows loopback socket 初始化錯誤，設定正式暫存路徑仍失敗。本批權限測試成功證據來自上表 Linux CI，不將本機啟動失敗計為通過。

## 2026-11-06 真實旅伴登入增量

帳號持有人在 production preview 的單一登入頁輸入既有 viewer 密碼後，登入成功；沒有再次貼 Firebase config、建立專案或操作六步精靈。網站顯示「已登入網站」，只列出唯一獲授權的共享合成旅程。既有 owner 分頁亦保留登入，沒有為了新驗收而登出。

- 成員管理實際顯示「檢視者（唯讀）」；新增／管理群組、新增／編輯費用、成員權限控制停用。USD 100 與 TWD 300 分別呈現，原備註讀回。
- 每日行程顯示跨年三日、下一站租車備註、Google Maps 連結及主要／備用停車連結；切換第二天讀回航班的出發／抵達日期及各自時區。
- 安全呈現測試字串仍以文字呈現，行程列表中沒有產生注入的 `img` 節點。
- 最新候選提交 `4297eeb` 的 [CI](https://github.com/fishingwithbag/Travel-OS/actions/runs/42055601378) 全部通過。89 個可達 commit 及重新建立的通用產物憑證／個資掃描無命中。

本項關閉的是「本機 production preview 的執行時網站設定與旅伴真實登入」；未將其當成建立者首次 Pages 部署或直接越權請求成功。直接 SDK 權限驗收頁已在本機準備，使用同一測試專案的既有三帳號，待帳號持有人集中輸入密碼；只建立新合成資料，不修改既有旅程。
