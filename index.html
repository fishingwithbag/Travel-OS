      STEP 1 · YOUR WEBSITE

      先確認你有自己的 Travel OS 網站

      正式雲端模式必須在你自己控制的網站中設定。GitHub Pages 可以免費託管這個網站；Travel OS repository 已經準備好 GitHub Actions，不需要你寫部署程式。

      你現在開啟的網站⚠ 您目前開啟的是官方 Demo 教學網址，請勿在此設定 Firebase、Google API Key 或登入帳密。請先建立自己的 Travel OS 網站，再進行正式設定。如果這是你自己的 GitHub Pages 或自訂網域，就可以繼續。
      1. 登入 GitHub，開啟 Travel OS repository。
      2. 點右上方附近的 Use this template → Create a new repository。
      3. Owner 選你的帳號；Repository name 建議填 Travel-OS；GitHub Free 請選 Public。
      4. 建立後進入你的 repository → Settings → 左側 Pages。
      5. 在 Build and deployment 的 Source 選 GitHub Actions。
      6. 到 Actions 頁面等待 Pages workflow 變成綠色成功，再回 Settings → Pages 點 Visit site。

      STEP 2 · FIREBASE

      建立免費的 Firebase 雲端同步

      Firebase 負責 Travel OS 的登入、旅程資料與多人同步。這個 Firebase 專案請維持 Spark 免費方案，不要替它連結 Cloud Billing（雲端帳單）；下一步的 Google Maps 外部導航不需要 API Key。

      看到「帳單 / Blaze」時先停下來此設定流程不需要啟用付費 Google Maps API。Firebase 專案若連結 Cloud Billing（雲端帳單），會升級成 Blaze；請確認仍使用 Spark。
      1. 建立 Firebase 專案：開啟 Firebase 控制台 → 建立專案。專案名稱可填 My Travel OS。Google Analytics 可略過，並維持 Spark 免費方案。
      2. 註冊網頁應用程式：進入 專案總覽 → 點 </> 網頁（若已有應用程式，點「新增應用程式」→「網頁」）→「應用程式暱稱」填 Travel OS → 不要勾選 Firebase Hosting → 按「註冊應用程式」。
      3. 啟用電子郵件／密碼登入：左側進入 Authentication（驗證） →「開始使用」→「登入方式」→「電子郵件地址/密碼」→ 啟用 →「儲存」。不要啟用「電子郵件連結」。
      4. 建立你的登入帳號：Authentication →「使用者」→「新增使用者」→ 輸入你自己的電子郵件與密碼。這組帳密稍後會填回 Travel OS。
      5. 建立 Realtime Database：左側進入 Realtime Database →「建立資料庫」→ 選擇適合的位置 → 起始安全規則選 鎖定模式 →「完成」。不要選測試模式。
      6. 複製 Realtime Database URL：留在 Realtime Database →「資料」頁籤。頁面上方會顯示一串以 https:// 開頭的資料庫網址，旁邊有連結圖示。請只複製上方這串網址，不要複製資料區裡顯示的 /: null。
      7. 部署 Travel OS 規則：Realtime Database →「規則」頁籤 → 將原本內容全部替換成 Travel OS Rules → 按「發布」。Firebase Rules 會在伺服器端保護每次讀寫。
      8. 取得 firebaseConfig：左側「設定」齒輪 →「專案設定」→「一般」→ 往下找到「您的應用程式」→ Travel OS →「SDK 設定與配置」→ 選「設定」。
      9. 複製 firebaseConfig：從 const firebaseConfig = { 開始，一路複製到最後的 };。不用自己加入 databaseURL；Travel OS 會把你上一步另外複製的 Realtime Database URL 自動合併進設定。

      STEP 3 · MAPS NAVIGATION

      Google Maps 導航已可直接使用

      Travel OS 目前只會開啟 Google Maps 網站，讓你搜尋景點、餐廳或停車場。這使用 Maps URL，不需要 Google Cloud 專案、Billing 或 API Key。

      1. 建立行程時可填地點名稱、地址，或貼上 Google Maps 分享連結。
      2. 在「下一個安排」或每日時間軸按 Google Maps，即可開啟目的地或停車場導航。
      3. 確認後按「下一步」，前往 Firebase 帳號登入。
      目前不會向你索取 Google API Key若未來加入站內地圖或 Places 搜尋，才需要另一個受 Website/API restrictions 保護的 Browser Key 與獨立 Google Cloud 專案；Server Key 一律不能貼進瀏覽器。

      STEP 4 · SIGN IN

      輸入你剛才在 Firebase Authentication 建立的帳號

      這不是 Google Cloud IAM。Authentication 只負責回答「現在登入 Travel OS 的人是誰」；Travel OS 的 owner／editor／viewer 是另一層旅程權限。

      帳號來源：Firebase 控制台 → Authentication（驗證）→「使用者」→「新增使用者」。Travel OS 不會保存你的密碼。

      STEP 5 · VERIFY

      最後由 Travel OS 自動檢查

      按下驗證後，Travel OS 會登入你的 Firebase，並在你的 UID 範圍內測試 Realtime Database 寫入、讀取與刪除。Google Maps 外部導航不需要驗證 API Key。

      「登入成功」不代表 Rules 一定安全Travel OS repository 另外用 Firebase Emulator 測試 owner/editor/viewer 與跨旅程拒絕。這裡只確認你的 self-host 設定可以正常連線與合法讀寫。

      READY

      你的 Travel OS 雲端已連線

      接下來可以建立第一趟旅程。若之後要讓旅伴登入，先到 Firebase 控制台 → Authentication（驗證）→「使用者」→「新增使用者」建立他們的帳號；旅程內的 owner／editor／viewer 權限由 Travel OS 資料與 Rules 控制，不是 Google Cloud IAM。
