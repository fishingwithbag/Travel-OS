      SETUP

      設定你的 Travel OS

      照著畫面一步一步完成即可，不需要先懂 GitHub、Firebase 或 Google Cloud。

      你現在使用的是官方公開體驗站

      這個網站只提供本機模式，不接受你的 Firebase config、Google API Key 或密碼。要使用雲端同步，請先建立一份由你自己控制的 Travel OS 網站。

      查看完整自行部署步驟
      本機模式資料只保存在這台裝置

      STEP 1 · YOUR WEBSITE

      先確認你有自己的 Travel OS 網站

      正式雲端模式必須在你自己控制的網站中設定。GitHub Pages 可以免費託管這個網站；Travel OS repository 已經準備好 GitHub Actions，不需要你寫部署程式。

      你現在開啟的網站如果這是你自己的 GitHub Pages 或自訂網域，就可以繼續。
      1. 登入 GitHub，開啟 Travel OS repository。
      2. 點右上方附近的 Use this template → Create a new repository。
      3. Owner 選你的帳號；Repository name 建議填 Travel-OS；GitHub Free 請選 Public。
      4. 建立後進入你的 repository → Settings → 左側 Pages。
      5. 在 Build and deployment 的 Source 選 GitHub Actions。
      6. 到 Actions 頁面等待 Pages workflow 變成綠色成功，再回 Settings → Pages 點 Visit site。
      建立自己的 Travel OS repositoryGitHub 官方 Pages 說明

      STEP 2 · FIREBASE

      建立免費的 Firebase 雲端同步

      Firebase 負責 Travel OS 的登入、旅程資料與多人同步。這個 Firebase Project 請維持 Spark 免費方案，不要替它連結 Cloud Billing；Google Maps 會在下一步使用另一個 Google Cloud Project。

      看到 Billing / Blaze 時先停下來Firebase 官方說，Spark 專案若連結 Cloud Billing，或在同一 project 使用 Google Maps API，會升級成 Blaze。這就是為什麼 Travel OS 把 Firebase 與 Google Maps 分成兩個 project。
      1. 建立 Firebase Project：開啟 Firebase Console → Create a project / 建立專案。Project name 可填 My Travel OS。Google Analytics 可略過。保持 Spark 免費方案。
      2. 建立 Web App：進入 Project Overview → 點 </> Web（若已有 App，點 Add app → Web）→ App nickname 填 Travel OS → 不要勾 Firebase Hosting → Register app。此時先不要複製 config。
      3. 啟用登入：左側 Build / Security → Authentication → Get started → Sign-in method → Email/Password → Enable → Save。不要開 Email link。
      4. 建立你的登入帳號：Authentication → Users → Add user → 輸入你自己的 Email 與密碼。這組帳密稍後會填回 Travel OS。
      5. 建立 Realtime Database：左側 Build / Databases & Storage → Realtime Database → Create database → 選適合你的 location → 起始規則選 Locked mode → Done。不要選 Test mode。
      6. 部署 Travel OS Rules：Realtime Database → Rules / Security Rules → 將原本內容全部替換成 Travel OS Rules → Publish。Firebase Rules 會在伺服器端保護每次讀寫。
      7. 最後再取得 firebaseConfig：左上齒輪 ⚙ → Project settings → General → 往下找到 Your apps → Travel OS → SDK setup and configuration → 選 Config。
      8. 複製的範圍：從 const firebaseConfig = { 開始，一路複製到最後的 };。不要複製 npm install、import 程式碼，也不要只複製 apiKey。
      開啟 Firebase Console
      查看 Firebase 官方文件

      Travel OS 只會讀取公開的 Firebase Web config。Service Account、private key、Admin SDK 憑證會被拒絕。

      STEP 3 · GOOGLE MAPS

      建立另一個 Google Maps Project 與 Browser Key

      這個 project 專門給 Google Maps 使用，和上一頁的 Firebase Spark project 分開。Google Maps 正式使用需要 Billing 與 API Key。

      1. 開啟 Google Cloud Console，建立新的 project，例如 My Travel OS Maps。不要選上一頁的 Firebase project。
      2. 在這個 Maps project 的 Billing 連結付款帳戶。Google Maps Platform production 需要 Billing。
      3. 到 Google Maps Platform / APIs & Services 啟用 Maps JavaScript API、Places API、Places API (New)。
      4. 到 Google Maps Platform → Keys & Credentials → Create credentials → API key。
      5. 點進剛建立的 Key。Application restrictions 選 Websites，加入下方 Travel OS 顯示的 Website referrer。
      6. API restrictions 選 Restrict key，只允許 Maps JavaScript API、Places API、Places API (New)。不要保留 unrestricted。
      7. 到各 API 的 Quotas 設合理的 request 上限；到 Billing 建立 Budget & alerts。Budget alert 是通知，不是硬性停用，所以 quota 仍然需要。
      Website restriction 請填Travel OS 使用 origin 等級的 referrer 驗證。Browser Key 在瀏覽器中可見；安全靠 Website/API restrictions 與 quota，不靠把 Key 隱藏起來。
      開啟 Google Maps Platform CredentialsGoogle 官方 API Key 設定Google 官方 Key 安全指南

      不要把 Server Key 貼在這裡。Routes／Geocoding／Weather 未來只能由你自己的後端使用 Server Key。

      STEP 4 · SIGN IN

      輸入你剛才在 Firebase Authentication 建立的帳號

      這不是 Google Cloud IAM。Authentication 只負責回答「現在登入 Travel OS 的人是誰」；Travel OS 的 owner／editor／viewer 是另一層旅程權限。

      帳號來源：Firebase Console → Authentication → Users → Add user。Travel OS 不會保存你的密碼。

      STEP 5 · VERIFY

      最後由 Travel OS 自動檢查

      按下驗證後，Travel OS 會依序確認 Google Maps/Places、Firebase Authentication、Realtime Database 與 Rules。測試只在你自己的 Firebase 範圍內執行。

      「登入成功」不代表 Rules 一定安全Travel OS repository 另外用 Firebase Emulator 測試 owner/editor/viewer 與跨旅程拒絕。這裡只確認你的 self-host 設定可以正常連線與合法讀寫。

      READY

      你的 Travel OS 雲端已連線

      接下來可以建立第一趟旅程。若之後要讓旅伴登入，先到 Firebase Console → Authentication → Users → Add user 建立他們的帳號；旅程內的 owner／editor／viewer 權限由 Travel OS 資料與 Rules 控制，不是 Google Cloud IAM。
