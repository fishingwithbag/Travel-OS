      CLOUD ONBOARDING

      雲端同步設定精靈

      使用你自己的 Firebase 與 Google Cloud。Travel OS 不提供中央雲端，也不會把你的資料送到維護者的 Firebase。

      公開體驗站不接受 Firebase、API key 或帳號密碼

      這個網站由 repository 維護者部署。為避免使用者把雲端憑證輸入他人控制的網頁，這裡只開放本機模式。需要雲端同步時，請先建立由自己控制的網站副本。

      查看自行部署步驟
      本機模式資料只保存在這台裝置

      STEP 1 · FIREBASE

      連接你自己的 Firebase

      僅接受網頁應用程式的公開連線設定。請勿貼上 service account 或私鑰。

      改用逐欄輸入
      還沒有 Firebase？查看建立步驟
      1. 先將 Travel OS 部署到自己控制的網站。
      2. 在 Firebase Console 建立專案及 Web app。
      3. 建立 Realtime Database，並部署本專案提供的安全 Rules。
      4. 在 Authentication 啟用 Email/Password，並在 Users 建立登入帳號。
      5. 複製 Web app 的完整 config 貼到上方。

      STEP 2 · GOOGLE MAPS

      建立你自己的 Browser Key

      欄位會遮罩，但 Browser Key 在瀏覽器端技術上不是秘密。真正的防盜機制是 Website restrictions、API restrictions、配額與帳務警示。

      這個網站建議授權的 Website referrer不要把 Key 設成 unrestricted，也不要把 Server Key 貼到這裡。
      Google Cloud Console 申請與防盜設定
      1. 進入 Google Cloud Console，建立或選擇你自己的 project，並連結 Billing。
      2. 在 Google Maps Platform 啟用 Maps JavaScript API、Places API 與 Places API (New)。
      3. 到 Google Maps Platform → Keys & Credentials，選擇 Create credentials → API key。
      4. 編輯該 Key，Application restrictions 選 Websites，加入上方顯示的網站 referrer。正式站與本機開發網址請分別加入。
      5. API restrictions 選 Restrict key，只勾選 Maps JavaScript API、Places API、Places API (New)。
      6. 到 Quotas 設定合理的每日／每分鐘上限；到 Billing 建立預算與告警。預算告警本身不是硬上限，所以仍要搭配 quota。
      7. 儲存後把這把 Browser Key 貼回上方；設定精靈會實際載入 Maps JS 並驗證 Places。

      Google 官方 API Key 安全指南 · 開啟 Google Maps Platform Credentials

      Server Key 不在這個精靈輸入。未來 Routes／Geocoding／Weather 必須使用你自己後端的 Secret Manager 或等效 secret storage。
