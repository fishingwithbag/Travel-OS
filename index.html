                STEP 1 · YOUR WEBSITE

                先確認你有自己的 Travel OS 網站

                正式雲端模式必須在你自己控制的網站中設定。GitHub Pages 可以免費託管這個網站；Travel OS repository 已經準備好 GitHub Actions，不需要你寫部署程式。

                你現在開啟的網站⚠ 您目前開啟的是官方 Demo 教學網址，請勿在此設定 Firebase、Google API Key 或登入帳密。請先建立自己的 Travel OS 網站，再進行正式設定。如果這是你自己的 GitHub Pages 或自訂網域，就可以繼續。
                1. 還沒有 GitHub 帳號？先依 GitHub 官方說明註冊，完成電子郵件驗證，再登入 GitHub；已有帳號就直接登入。然後開啟 Travel OS repository。
                2. 點右上方附近的 Use this template → Create a new repository。
                3. Owner 選你的帳號；Repository name 建議填 Travel-OS；GitHub Free 請選 Public。
                4. 建立後進入你的 repository → Settings → 左側 Pages。
                5. 在 Build and deployment 的 Source 選 GitHub Actions。
                6. 到 Actions 頁面查看 Deploy GitHub Pages。若尚未執行，選它並按 Run workflow（branch 選 main）；若先前因尚未開啟 Pages 而失敗，也請在此重新執行。看到綠色成功後，再回 Settings → Pages 點 Visit site。

                STEP 2 · FIREBASE

                建立免費的 Firebase 雲端同步

                Firebase 負責 Travel OS 的登入、旅程資料與多人同步。請維持 Spark 免費方案，不需要付款資料、Google Cloud 計費帳戶或部署 Functions。

                保持 Spark，不連結計費帳戶連結 Cloud Billing 會使 Firebase 專案成為 Blaze。Travel OS 不需要這個步驟；Spark 額度不足時請備份並使用本機模式，不需升級付費。
                1. 建立 Firebase 專案：先用自己的 Google 帳戶登入 Firebase 控制台；沒有 Google 帳戶就先依官方說明建立。按 建立專案，名稱可填 My Travel OS。如果 Gemini in Firebase 或 Google Analytics 預設開啟，可在建立流程中關閉；Travel OS 不需要這兩項。維持 Spark 免費方案。這個 Firebase 專案本身也會是 Google Cloud 專案，不必再建一個給目前的 Maps 導航。
                2. 註冊網頁應用程式：進入 專案總覽 → 點 </> 網頁（若已有應用程式，點「新增應用程式」→「網頁」）→「應用程式暱稱」填 Travel OS → 不要勾選 Firebase Hosting → 按「註冊應用程式」。
                3. 啟用電子郵件／密碼登入：左側進入 Authentication（驗證） →「開始使用」→「登入方式」→「電子郵件地址/密碼」→ 啟用 →「儲存」。不要啟用「電子郵件連結」。
                4. 建立你的登入帳號：Authentication →「使用者」→「新增使用者」→ 輸入你自己的電子郵件與密碼。這組帳密稍後會填回 Travel OS。
                5. 建立 Realtime Database：左側進入 Realtime Database →「建立資料庫」→ 選擇適合的位置 → 起始安全規則選 鎖定模式 →「完成」。不要選測試模式。
                6. 複製 Realtime Database URL：留在 Realtime Database →「資料」頁籤。頁面上方會顯示一串以 https:// 開頭的資料庫網址，旁邊有連結圖示。請只複製上方這串網址，不要複製資料區裡顯示的 /: null。
                7. 部署 Travel OS 規則：Realtime Database →「規則」頁籤 → 將原本內容全部替換成 Travel OS Rules → 按「發布」。Firebase Rules 會在伺服器端保護每次讀寫。
                8. 取得 firebaseConfig：左側「設定」齒輪 →「專案設定」→「一般」→ 往下找到「您的應用程式」→ Travel OS →「SDK 設定與配置」→ 選「設定」。
                9. 複製 firebaseConfig：從 const firebaseConfig = { 開始，一路複製到最後的 };。不用自己加入 databaseURL；Travel OS 會把你上一步另外複製的 Realtime Database URL 自動合併進設定。
                開啟 Firebase 控制台
                查看 Firebase 官方文件
                建立 Google 帳戶建立網頁應用程式／firebaseConfig電子郵件／密碼驗證Realtime DatabaseRealtime Database 安全規則Spark / Blaze 方案

                Travel OS 只會讀取公開的 Firebase 網頁設定。服務帳戶（Service Account）、私密金鑰（private key）、Admin SDK 憑證都會被拒絕。firebaseConfig 裡沒有 databaseURL 也沒關係。

                取得位置：Firebase 控制台 → Realtime Database →「資料」頁籤 → 複製頁面上方顯示的 HTTPS 網址。不要複製下方資料樹中的 /: null。

                貼上後按「下一步」，Travel OS 會先確認 Project ID、Auth Domain 與 Realtime Database URL。

                STEP 3 · GOOGLE MAPS

                設定 Google 搜尋與交通估算

                基本導航：景點、停車場及開車／步行路線透過 Google Maps 外部連結開啟。不需建立 API 金鑰、不需 Google Cloud、不需連結計費帳戶，直接下一步即可。

                先確認你的零費用要求Google Cloud「免費試用帳戶」有期限，並非永久免費方案；不升級時，試用到期或抵免用完會停止相關服務。將帳單帳戶連結至 Firebase 專案會使 Firebase 自動轉為 Blaze，即使 Cloud 帳戶仍是免費試用。若必須維持 Spark，請勿對同一專案連結帳單。Travel OS 不會替你升級帳戶，也無法保證 Google API 永遠零費用。Firebase 方案與帳單連結說明Google Cloud 免費試用到期說明
                1. 在新增安排中手動輸入地點名稱或地址。
                2. 若要精確定位，從 Google Maps 複製分享連結，貼到安排的「Google Maps 連結」欄位。
                3. 主要與備用停車場可各自填入名稱及地圖分享連結；每日行程與下一個安排會分開顯示。
                4. 相鄰安排可開啟 Google Maps 開車或步行路線，路程與時間在 Google Maps 查看。
                1. 建立另一個 Google Cloud 專案：Project ID 不可與上一步 Firebase 專案相同。Maps API 要求連結帳單；若沿用 Firebase 專案，Firebase 會離開 Spark。看到 Google 要你替 Firebase Project ID 設定帳單時，請按取消並回來建立新專案。
                2. 依官方說明確認 Google Maps 的計費及免費額度條件，啟用 Maps JavaScript API、Places API (New) 與 Routes API。免費額度不等於無上限免費，預算通知不會自動停止用量。
                3. 建立瀏覽器 API Key，將網站限制設為自己的網站，API 限制只勾選實際使用的服務。不要貼服務帳戶私鑰或伺服器憑證。
                4. 按下方「Google 功能設定」貼上 Key 並套用，可選擇記住此裝置。SDK 載入檢查只確認程式載入，不代表服務或額度已驗證。
                5. 建立旅程後，在「新增景點」實際搜尋及選取；再新增兩站，在「站內路程與時間估算」實測。兩項都成功才算 Google 功能驗證完成。
                Google 官方免 Key Maps URL 說明

                STEP 4 · SIGN IN

                輸入你剛才在 Firebase Authentication 建立的帳號

                這不是 Google Cloud IAM。Authentication 只負責回答「現在登入 Travel OS 的人是誰」；Travel OS 的 owner／editor／viewer 是另一層旅程權限。

                帳號來源：Firebase 控制台 → Authentication（驗證）→「使用者」→「新增使用者」。Travel OS 不會保存你的密碼。

                STEP 5 · VERIFY

                最後由 Travel OS 自動檢查

                按下驗證後，Travel OS 會登入你的 Firebase，並在你的 UID 範圍內測試 Realtime Database 寫入、讀取與刪除，以及目前儲存格式所需的 Rules。若仍使用舊版 Rules，請回 Step 2 複製並發布目前版本。本步不驗證 Google 搜尋或交通估算，也不部署 Functions；請在 Firebase 控制台確認 Spark。

                「登入成功」不代表 Rules 一定安全Travel OS repository 另外用 Firebase Emulator 測試 owner/editor/viewer 與跨旅程拒絕。這裡只確認你的 self-host 設定可以正常連線與合法讀寫。

                READY

                你的 Travel OS 雲端已連線

                接下來可以建立第一趟旅程。若之後要讓旅伴登入，先到 Firebase 控制台 → Authentication（驗證）→「使用者」→「新增使用者」建立他們的帳號；旅程內的 owner／editor／viewer 權限由 Travel OS 資料與 Rules 控制，不是 Google Cloud IAM。
